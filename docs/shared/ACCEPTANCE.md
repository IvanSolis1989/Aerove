# 架构迁移验收契约

本文件定义AEROVE Lite与标准版界面、交互和客户端功能完全一致所需证据，不是已经取得的性能结果。只有固定Rust核心源码证明不支持的能力可暂缓；例外只作开发记录，APP不提供其功能项、占位、灰置开关或开发清单，不能以功能差异或降低画质冒充性能收益。

后续用户明确收紧：除有源码证据的Rust核心能力限制外，所有客户端功能和界面均须一致，且任何一版的微调必须双向同步。缺少移植或桥接不构成发行例外。以[双实现硬契约](UI_CONTRACT.md)为准，当前实现差异未消除前不得宣布交付完成。

长期目标是由原生Android版替换现有Android版，现阶段双版本分开。最优能效是测量目标，不能在缺少同设备实测时宣称“安卓最优”或把Rust视为固定赢家；替换须在实际收益、功能、视觉和可靠性达标后进行。

## 基线与可比性

- 产品基线使用已验收的稳定源和APK，固定实际构建SHA、签名、依赖、设备/系统/GPU、刷新率、亮度、配置及数据规模。
- 前端对照固定同一核心与网络工作负载；核心对照固定同一前端和测试服务。不要同时替换两者再把差异全部归因于其中一项。
- Flutter和原生都用优化release构建；原生启用匹配的R8/Baseline Profile策略并记录，不能拿原生release和Flutterdebug比较。
- 网络核心试验只在授权的隔离容器/模拟器或测试设备进行，不接管工作主机的系统代理、路由、DNS或已安装客户端。

## 视觉与交互

用户已确认Lite首版最低Android13（API33）；这也是完整清透效果的验收下限。标准版的旧系统兼容范围保持不变。

逐项对照简约纯色、柔光磨砂、流光清透，分别组合普通主题/灵动极光、深浅色、开启与关闭、普通与选中、减少动态效果、大字体以及透明叠层。

- 纯色不得因底图开启而出现模糊、折射或玻璃描边；磨砂各表面一致且不残留清透边；清透必须有真实背景位移而非仅半透明填充。
- 连续圆角、旗面停稳后的完整边界居中、气泡运动、材质取色和文字对比度规则均保留。
- 覆盖滚动吸顶、重叠菜单/弹层/导航、键盘/返回、动画反向、旋转和可访问性。单张静态截图不证明动态捕获或生命周期正确。
- Lite不提供API32及以下的降级路径；在API33+验证AGSL折射，不将普通透明控件当作清透替代。

## 核心功能契约

固定实际使用的订阅样本及合成fixture，比较协议/传输、UDP、DNS fake-IP/IPv6、域名/规则集/策略组、provider更新/持久化、测速/取消、连接观测和关闭、配置失败后的恢复。

- 编译配置前做能力校验，未知或不能保真的字段返回具体位置，不能忽略Mihomo字段后假称订阅导入成功。
- 功能入口由已验收的能力集合决定；核心不支持时对应选项不进入APP。导入错误只解释当前配置的问题，不变成开发缺口清单。缺失的可选能力本身不阻止限定支持范围的Lite发布，但不允许宣称与标准版完全兼容。
- Android必须验证外部TUN fd接管与关闭、VpnService.protect、网络切换、Always-on/revoke、进程回收与运行中接管；UID/包归属等能力实现后才加入入口并验收。桌面必须保留lease/helper权限、完整性和单实例停止确认。
- 启停竞争、错误封装、丢失/过量事件、后台暂停/恢复与配置变更属于产品契约，不由某个核心的REST API碰巧类似就省略。

## 性能和内存口径

记录冷/温启动、长列表交互的帧分布和丢帧、CPU/GPU时间、线程与唤醒、进程PSS/RSS、图形/纹理、Dart/ART/Go/Rust分配、持续流量吞吐/延迟、空闲及后台状态。使用Perfetto/Macrobenchmark与设备可用的内存/功耗采样，重复实验并记录离散度、热降频和测量限制。

当前Android核心与界面同进程。`MemorySnapshot.resolve`把Go运行时记账从进程RSS中减出，展示的App余量不是纯Flutter堆，仍含原生分配、图形和其他进程映射。不能把这个数字直接作为删除Flutter后的节省量；也不能把同进程核心RSS再相加。

同画质下原生依然需要离屏纹理、采样和着色器。要分别验证背景捕获共享、按需绘制、可见性裁剪、后台暂停，不能通过关闭折射/极光或减少协议支持制造性能优势。

性能比较先固定共同支持的功能、数据、平台及视觉契约，再比较在目标设备上稳定复现的收益。Lite相对标准版的能力差异保留在开发矩阵中，不算作性能优化。没有设备结果时标记未验证；不发布固定省电百分比、内存降幅或“原生/Rust必然更快”的结论。

## 发布和回滚

保留包名、持久签名、Android编号单调递增和数据迁移。候选使用清楚区分的构建/通道，不覆盖稳定latest。原APK只构建一次并按来源推广，正式下载资产和说明验收后才宣布发布完成。
