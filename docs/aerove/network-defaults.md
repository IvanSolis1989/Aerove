# Standard network defaults: recorded baseline

[Documentation](../README.md) / [Standard](README.md)

This document records an earlier pinned baseline, not a claim that every value below is the current build default. In particular, the later [defaults audit](defaults.md) records changes to IPv6, and bundled script versions have advanced. Check the installed build's source metadata and current settings before relying on a historical value. Regional routing and DNS rules are technical configuration choices, not a promise of service availability or a product targeted at a particular nationality.

The recorded baseline uses the [Smart-Config-Kit FlClash script](https://github.com/IvanSolis1989/Smart-Config-Kit/tree/main/FlClash). The script owns service resolvers, domain policies, fallback chains and private-node adaptation. The client overrides only the bootstrap resolvers with these four DoH-over-IP endpoints, with no plaintext fallback or upstream FlClash default resolver list:

```text
https://223.5.5.5/dns-query
https://223.6.6.6/dns-query
https://8.8.8.8/dns-query
https://1.1.1.1/dns-query
```

This is historical provenance, not the current bundled-version claim.

The bundled body works offline. Advanced configuration → Scripts exposes its remote source for editing, copying or opening, and the existing sync action fetches updates. The recorded URL was:

```text
https://raw.githubusercontent.com/IvanSolis1989/Smart-Config-Kit/main/FlClash/FlClash%28mihomo%29.js
```

That historical path may have moved; current product source metadata governs current update links. Application upstream updates and script updates are separate processes. Subscription auto-update must not be described as script auto-update; no update interval is inferred from the source repository.

<a name="section-2"></a>
## DNS ownership

The [pinned Android guidance](https://github.com/IvanSolis1989/Smart-Config-Kit/blob/6847cd225d70bc9eb6fdd9311d50ff53bc91981c/FlClash/README.md#L113-L152) disables appending system DNS on new installations. Only `default-nameserver` is selected for the client override; other DNS override keys remain unselected. After the script runs, every other DNS field must match its output, including unknown keys, list order and dynamic-node policies. Resetting defaults retains this bootstrap policy rather than returning to the upstream resolver list.

| Item | Recorded script behavior |
|---|---|
| China-domain and direct resolution | AliDNS and DNSPod DoH |
| Other-domain policies and fallback | Cloudflare and Google DoH |
| `respect-rules`, `direct-nameserver-follow-policy` | `true` |
| DNS IPv6, `prefer-h3`, `use-system-hosts` | `false` in this historical snapshot |
| Private nodes | Preserve exact active-node `proxy-server-nameserver-policy` generated by `adaptive` |
| Fake-IP | Preserve the script's filter list and input-mode handling; do not recreate the list |
| Source `listen`, `enhanced-mode` | Preserve the script's fill-only-if-missing semantics |
| Bootstrap | Only the four DoH-over-IP endpoints; no old plaintext `223.5.5.5` fallback |

Do not replace this configuration solely to change a test website's country label. A DNS country label does not establish the actual traffic exit or prove a leak. See the [Mihomo DNS reference](https://wiki.metacubex.one/config/dns/).

<a name="section-3"></a>
## Recorded Android installation defaults

These are the historical new-install defaults, not forced rewrites of upgrades, restored backups or saved settings.

| Setting | Recorded value | Reason or boundary |
|---|---|---|
| VPN / routing mode | Enabled / rule | Pinned Android guidance |
| VPN system proxy | Disabled | Avoid an additional HTTP proxy declaration interfering with VPN routing |
| VPN IPv6 / core IPv6 | Both disabled in this snapshot | Separate switches; see the later defaults audit for changes |
| DNS hijack | Enabled | Capture plaintext DNS entering TUN |
| Application access control / allow VPN bypass | Both disabled | Route applications through Mihomo under this baseline |
| App DNS overrides | Only `default-nameserver` | Encrypted bootstrap; preserve other script DNS output |
| Append system DNS | Disabled | Do not append `system://` |
| TCP concurrency / unified delay | Enabled | Script behavior |
| Keep-alive idle / interval | 30 / 15 seconds | Preserve script values through post-processing |
| TUN stack, MTU, congestion control, GeoX | Client defaults | App-owned, not copied from unrelated client examples |

The recorded `mips` stack is documented by [Mihomo](https://wiki.metacubex.one/config/inbound/tun/). Do not change stack or MTU without local network measurements. There is no separate legacy “routing mode” UI field to copy; use the client's actual configuration routes and exclusion lists.

`allowBypass=false` revokes ordinary applications' permission to bind directly to underlying networks ([Android API](https://developer.android.com/reference/android/net/VpnService.Builder#allowBypass())). It does not disable the core's `protect` callback and is not Android's system-level kill switch. Private-network route bypass retains LAN compatibility. Excluded apps, excluded routes and applications' own encrypted DNS require device-path verification; equality of a DNS configuration dictionary is not whole-device acceptance.

<a name="section-4"></a>
## Verification boundary

Source checks, baseline/private-node cases and deep comparison of final DNS configuration prevent unintended client rewrites. Device tests must still verify VPN authorization, effective configuration after restart, excluded applications, traffic exits and DNS paths. Static or synthetic tests do not prove zero leaks on every device.

## DNS 所有权

按[源仓库 Android 建议](https://github.com/IvanSolis1989/Smart-Config-Kit/blob/6847cd225d70bc9eb6fdd9311d50ff53bc91981c/FlClash/README.md#L113-L152)，
新安装关闭“追加系统 DNS”。应用层只覆写 `default-nameserver` 为上述四个加密地址；
这项是用户明确要求的客户端策略，其余 DNS 覆写键不选中。
脚本执行后，除这一项外，最终送入核心的 `dns` 必须与脚本输出逐字段相同，
包括未知字段、列表顺序和动态节点策略。恢复默认也使用同一套用户 DNS，不回到原版列表。

| 项目 | 采用的脚本行为 |
| --- | --- |
| 国内业务和直连解析 | AliDNS、DNSPod DoH |
| 海外域名策略与 fallback | Cloudflare、Google DoH |
| `respect-rules`、`direct-nameserver-follow-policy` | `true` |
| DNS IPv6、`prefer-h3`、`use-system-hosts` | `false` |
| 私有节点 | 保留 `adaptive` 产生的活动节点精确 `proxy-server-nameserver-policy` |
| Fake-IP | 保留脚本过滤列表及对来源模式的处理，不重新手写列表 |
| 来源 `listen`、`enhanced-mode` | 保留脚本“缺省时补齐”的语义 |
| 自举解析器 | 仅四项 DoH-over-IP，移除旧明文 `223.5.5.5` 兜底 |

业务 DNS 仍按作者方案使用国内/海外 DoH，不能为了检测网站的国家标签而替换为全海外 DNS。
DNS 国家标签也不等于实际流量出口或泄漏结论。字段含义参考
[Mihomo DNS 文档](https://wiki.metacubex.one/config/dns/)。

<a name="section-3"></a>

## Android 默认设置

以下是新安装的基线；升级、备份恢复及已有用户设置不强制重写。

| 设置 | 默认 | 依据 |
| --- | --- | --- |
| VPN、规则模式 | 开启、规则 | 源仓库 Android 建议 |
| VPN 系统代理 | 关闭 | 避免额外的 HTTP 代理声明干扰 VPN 分流 |
| VPN IPv6、核心 IPv6 | 均关闭 | 两个独立开关，均与作者方案一致 |
| DNS 劫持 | 开启 | 接管进入 TUN 的明文 DNS |
| 应用访问控制、允许应用绕过 VPN | 均关闭 | 采用源仓库“全部应用交给 Mihomo 分流”的基线 |
| 应用层 DNS 覆写键 | 仅 `default-nameserver` | 强制采用用户要求的加密自举，其余脚本 DNS 保持原样 |
| 追加系统 DNS | 关闭 | 不向作者 nameserver 追加 `system://` |
| TCP 并发、统一延迟 | 开启 | 与源脚本一致 |
| keep-alive idle / interval | 30 / 15 秒 | 与源脚本一致，避免 App 后处理改回其他值 |
| TUN 栈、MTU、拥塞控制、GeoX | 保留客户端默认 | 由 App 管理，不从其他客户端示例移植 |

当前 `mips` 是 [Mihomo 文档](https://wiki.metacubex.one/config/inbound/tun/)支持的默认栈。
没有本机网络测量依据时，不以“国内优化”为由随意改成其他栈或 MTU。
客户端没有旧指南中的独立“路由模式”字段，实际使用其配置路由和排除表，不能照抄旧界面字段。

`allowBypass=false` 撤销普通应用主动绑定底层网络绕过 VPN 的许可，见
[Android 官方接口](https://developer.android.com/reference/android/net/VpnService.Builder#allowBypass())；
它不影响核心的 `protect` 回调，也不是 Android 的系统级 kill switch。
私网路由绕过保持原客户端的局域网兼容行为；被主动排除的应用、路由以及应用自己的加密 DNS
仍需结合设备路径检查，不能以 DNS 字典一致代替整机网络验收。

<a name="section-4"></a>

## 验证边界

脚本来源校验、基础与私有节点用例，以及最终配置 DNS 的深比较用于防止客户端意外改写作者方案。
Android 真机仍需核验 VPN 授权、重启后的实际配置、应用是否被排除、连接出口与 DNS 请求路径。
静态或合成测试通过不构成“所有设备绝对零泄漏”的证明。
