# Aerove 独立开发架构

状态：双产品并行实施中。标准版已有稳定发行，Lite 仍须完成共同功能与实际渲染/产物验收；本文件不宣称原生界面或第二核心已可发布。

## 双产品决策

用户最新目标：以Android原生渲染和经实测能效最优的核心实现下一代Android客户端，成熟后替换现有Android版。现阶段保留Aerove Flutter+Go/Mihomo，并独立开发AEROVE Lite；不提前删除稳定产品、迁移用户数据或改变桌面路线。Lite当前确定使用clash-rs，不打包Go回退。未来替换现有Android版仍以同功能、同画质、同负载实测为条件，不以语言或项目名称宣称节能优势。

| 事项 | Aerove | AEROVE Lite |
| --- | --- | --- |
| 当前状态 | 已有稳定交付，继续维护 | 独立验证阶段，尚无可发布APK |
| 界面 | Flutter，保持现有多平台路线 | Android13+，Compose+Backdrop2.0.1及材质适配 |
| 核心 | 现有已验证Mihomo/Go | 固定公开稳定clash-rs，需自有Android桥接 |
| 功能目标 | 保持现有协议、配置与平台兼容性 | 界面、交互和客户端功能完全一致；仅源码证明不支持的Rust核心能力可暂缓并记录例外 |
| 用户数据 | 现有包名/签名/数据和升级路径不变 | 独立包标识/数据/签名与版本通道，显式导入导出 |
| 共享 | 视觉规范、配置交换/诊断契约、测试向量、品牌资源及来源说明 | 不依赖Flutter、Go或标准版的运行时/构建链 |

AEROVE Lite使用白底黑飘带的独立图标，沿用原版符号的反色逻辑和折叠层次。母版位于`apps/aerove/assets_source/images/icon/lite/aerove-lite-icon-tile.png`，已接入`apps/aerove-lite/`的启动器和自适应图标；标准版图标保持不变。APK上的实际显示仍须设备验收。

### 一致性目标（用户最新约束）

Lite的目标是Android能效、流畅度和可靠性，轻量化指标包括安装包、运行时、内存、CPU/GPU和后台开销；界面、交互和客户端功能必须与Aerove一致且双向同步。以已发布1849及后续共同功能基线建立开发矩阵，视觉、数据刷新策略和功能变化都保留来源。性能对照固定双方共同支持的功能和画质，不把能力差异算作优化收益。两版并行是当前迁移策略；替换现有Android版还需实际收益、关键功能及稳定性达标，并准备签名、数据和升级路径。

- 视觉：简约纯色/柔光磨砂/流光清透、普通主题/灵动极光、普通/选中图文透色、连续圆角、气泡/旗面、玻璃层级、滚动/菜单/导航/键盘与无障碍。
- 功能：订阅与配置类型、节点/策略组、测速与实际出口、规则/规则集、DNS与IPv6、应用分流、脚本、资源、连接/请求/DNS观测、诊断和备份/恢复；按实际Android产品能力逐项验收。
- 核心例外：逐项以固定clash-rs源码及行为证据判定，记录SHA、字段和原因；不把缺少客户端包装、编辑器、脚本或桥接代码当作核心限制。例外不在APP放入口、占位或灰置开关。系统VpnService的分应用代理是宿主能力，必须实现。
- 配置边界：隐藏未支持的功能项不等于允许忽略配置。导入包含不支持能力的订阅或配置时，必须说明具体节点或字段及不能完整使用的原因；不能静默丢弃、擅自转换或宣称完全兼容。
- 发布边界：未消除的共同界面、交互或客户端功能差异均阻止发行，唯有上述源码证明的核心例外可暂缓。protect/TUN接管、启停关闭、网络切换和配置保真仍须验收。原型允许纵向切片，但不能作为完整产品发布。完整要求见[双产品开发契约](../shared/UI_CONTRACT.md)。

同一Android用户/工作资料同时只能有一个活动VPN。可以同时安装、分别查看界面，但切换VPN必须经系统授权与停止确认，不能承诺两套VPN并行工作。

用户已确认同一仓库、独立版本和发布入口。当前Aerove更新器读取本仓库Releases/latest；Lite不能抢占该latest，否则标准版可能收到错误APK。Lite使用独立标签和按产品选择的更新入口，发布时必须保持标准版latest。独立工程使用`dev.aerove.lite`，开发包为`dev.aerove.lite.dev`；尚未发布Lite资产。仓库已独立维护，历史来源、许可证和既有发行升级边界继续保留。

用户已确认Lite首版最低Android13（API33），并按VPN、订阅与本地配置、节点/代理组/测速、三模式、连接流量、日志、DNS、分应用、后台常驻、三档材质和灵动极光完成。GPU验收覆盖真实背景位移、折射、色散、叠层、开关及导航；标准版Android7兼容不变。

## 产品所有权

Aerove 按自身需求、版本和验证结果演进。FlClash 是已记录来源及可选择参考的项目，不再决定 Aerove 的版本号，不允许定时合并其开发分支或标签。依赖和参考变更要先形成可审阅补丁，再经过本产品的兼容性和发布验证。

标准版Mihomo直接跟踪MetaCubeX官方已公开发布的稳定版本，不等待FlClash。官方源码固定到真实提交，已有protect、UID、运行挂钩和代理组适配作为本仓库可重放补丁维护；不依赖第三方核心分支承载Aerove补丁，也不为此新建核心仓库。Lite的clash-rs有独立来源与验证链。具体纳入规则及GitHub fork网络关系的处理边界见[独立维护与来源参考](upstreams.md)。

保留已有 Git 历史、GPL-3.0 许可证、第三方版权、固定签名和用户数据兼容性。独立维护不等于删除来源，也不通过重建仓库或改包名来丢弃升级路径。

## 边界

- 产品域：配置来源、节点/策略组、测速、连接、DNS查询、资源、备份和用户选择；不以某个核心的原始结构作为跨前端的唯一领域模型。
- 配置编译：把产品设置和订阅合成为目标核心配置，显式校验支持的协议/规则/功能；无法保真时返回可定位错误，不静默丢字段。
- 核心适配：对生命周期、节点选择、测速、事件、统计和资源操作分别适配；平台RPC传输不是第二核心的实现。
- 平台宿主：Android VpnService/ServiceState独占VPN意图与文件描述符生命周期；桌面lease/helper独占进程。界面重建不意味着重启代理。
- 呈现：当前Flutter界面与未来原生Android界面都消费产品状态。渲染、视觉材质和动效不进入代理核心；窗口隐藏/后台不应维持无意义的绘制或遥测。
- 发布：标准版版本来自自身pubspec，Lite来自独立Gradle工程；固定来源、构建编号、签名、哈希和原APK推广仍是发布边界。

## 演进顺序与完成标准

1. 独立开发治理：解除最高FlClash标签和产品版本绑定，停止自动上游merge，保留血缘与依赖证明；发布工具真实入口及历史包验证通过。
2. 核心契约：从现有实际调用拆出能力和配置编译边界，为既有Mihomo建立同等行为回归；不添加无法启动的“可选核心”。
3. 原生视觉样板：先审计并复用已发布的Android/Compose液态玻璃库，优先验证Backdrop，比较Haze等候选；不默认从零重写捕获和折射引擎。固定依赖版本、来源和许可证后，在相同设备、画质和数据下覆盖清透/磨砂/纯色、极光、图文透色、旗面、叠层和交互，测量启动/PSS/帧耗时/后台功耗。缺口只在现成库无法满足且有源码/实测证据时作受控扩展。
4. Lite核心接入：以独立Android宿主接入固定公开稳定clash-rs，验证配置保真、protect/TUN/网络切换及吞吐/延迟/RSS/CPU/耗电；UID/package等可选能力按实际支持情况单独验收。不更换标准版核心，也不在Lite里偷偷打包Go回退。
5. Lite功能交付：完成全部共同界面、交互和客户端功能及其数据更新策略；唯一暂缓项来自可核查的核心例外。任何一版细节调整均双向同步，不用占位或灰置入口替代实现。现阶段两版独立交付，稳定版继续可用。
6. Android替换验收：固定设备、负载、协议和画质，分别比较前端与核心，验证功耗、帧时间、内存、后台唤醒及稳定性；核心可以按证据调整。达到目标后再实施Android迁移，不将开发预览包当作稳定替换，也不删除桌面支持。

## 正在查证的选择

- clash-rs：审计固定公开稳定v0.10.10，同时区分master新能力；不能以Rust语言直接证明比当前Mihomo节能或更快。
- Android原生：Compose组织交互，复用Backdrop的采样/缓存/合成，再适配Aerove材质与交互规则。首版只支持API33+，不将普通透明填充当作清透折射替代。
- 跨平台：Android原生并不自动提供Windows/macOS/Linux界面。Android优先的迁移需要明确桌面过渡路径，不能暗中删除平台支持。
